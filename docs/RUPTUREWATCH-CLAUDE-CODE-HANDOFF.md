## Short review

RuptureWatch already proves that pharmacy reports can produce explainable changes in a shared shortage signal. The part that could win is what comes next: how the next decision is made, who owns it, and what a different allocation would do. Recover the Phase 2.1 playbook as a usable product surface, then let a judge test its consequences. The strongest feature addition is an interactive comparison using two allocation rules with the same stock and hospital reserve.

### A. Interactive allocation comparison · 2–4 hours

On `/grossiste/repartition/[moleculeId]`, let the user change the stock and compare **Répartition proportionnelle à l’usage** with **Répartition selon les jours de couverture**. Add a non-persistent version to the existing fictional `/scenario` if schedule permits so a signed-out judge can try it without role setup.

- Put the comparison next to the existing boxes input. Start the scenario at the existing 2,500-box example. Use `fairSplit()` for the coverage-based result. Add a small pure helper in `lib/allocation/` for the proportional reference. Allocate whole boxes by estimated monthly usage with deterministic rounding and stable governorate-code ties. Apply the same hospital reserve, need cap and unallocated-stock rules to both. Redistribute surplus from capped rows among eligible rows. Label the proportional method as a **reference model**, without implying it is a wholesaler’s actual practice.
- Show **minimum days of cover** first, with a small before/after range plot, reserve and boxes allocated. Sort the detail table by least initial cover and expose all regions in the existing table. Give the two plotted results labels and distinct shapes. Keep the wholesaler’s existing record-decision action linked to the proposed model. Data remain labeled **Simulation**.
- **Fixture acceptance** — At 2,500 boxes, show 250 hospital reserve, 2,250 allocated, 11.0 days minimum under the reference model and 17.3 days under `fairSplit()` at one decimal. Derive values from the shared fixture and algorithms. Test inventory conservation, zero stock, cap saturation, all-zero demand, small stock with rounding, and the 2,500-box result.
- **Optional extension after A** — Add **Stock nécessaire pour viser 14 jours**, explicitly a simulated target chosen by the operator. The fixture needs 1,444 distributable boxes to reach 14 days in all modeled governorates, which first fits at 1,604 total boxes under the current floor-rounded 10% hospital reserve. Check adjacent inputs (1,603 and 1,604). If asking for a target beyond the policy horizon, show why the target falls outside the model.

### Guardrails against generic design

- Build the signature visual out of your own data: Tunisia’s outline, a shortage’s state sequence, and how cover changes with the same boxes. Reuse `GovernorateMap`, `LevelBand`, `LevelBadge`, `OriginBadge` and the existing chart primitives where they fit. Give every line, number and marker a job. Use full-color hero composition, generous typography and intentional white space to create personality.
- Use one meaningful illustration across the first viewport, one main action per view, and the existing icon set. Favor flat plum, clean surface colors and a clear reading order. Leave stock photography, glass effects, decorative gradients, floating badges, duplicate rail headers and animated counters out of the execution. A large number represents a computed result with a visible unit.
- Use existing route URLs and console chrome. Keep real operational data and simulated evidence labels legible in screenshots and printed notes. Store any new FR copy in `messages/fr/` and match public changes in `messages/ar/`. Route authors should prefer logical CSS properties and preserve the current LTR medicine-name wrapper.

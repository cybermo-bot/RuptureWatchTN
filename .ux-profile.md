# UX Profile

Written for RuptureWatch TN on 25 November 2026 (in place of running `setup-ui-ux-skills`). All UI/UX skills in this project read this file before changing layout, copy, or interaction. `DESIGN.md` and `CLAUDE.md` (§2 product rules, §4 principles, §9 design) win over anything here.

## Aesthetic reference

- **Standard:** Stripe
- **Notes:** Refined type (IBM Plex Sans, IBM Plex Mono for figures and identifiers), clear data, calm depth, hairline rows rather than stacks of cards. Public and pharmacy screens lean toward Apple Native spacing (generous, one action per screen, read in three seconds at a counter); coordination and centrale screens toward Stripe density. Cool neutrals (page `#F5F7F6`, band `#F3F6F5`), powder blue panels, petrol rail and scenario, dark blue action `#235c76`. Level colours always with their shape and word. Motion: short and purposeful, only real state changes.

## Banned anti-aesthetics

- Gratuitous glassmorphism (`backdrop-filter`), glows, neon borders, rainbow or multi-hue gradients, gradient text
- Decorative blob or mesh gradients, marquees, looping decoration
- Floating pastel pills for ordinary metadata
- Cartoon people or mascots; huge illustrations with no action
- Icons inside inputs unless functional (search, clear)
- Soft shadows as the only separator
- Nested scroll regions
- Disabled submit as the only feedback
- Project-specific: the plum / lavender / violet / citron palette of session 6 and branch `olfa`; Instrument Serif, Hanken Grotesk, DM Mono or any font other than IBM Plex; the 3D globe and Three.js; count-up or animated counters on real figures; magnetic, tilt or spotlight effects; blur reveals; cream or beige backgrounds; sideways page slides (French and Arabic share the layout); manufacturer box photos or stock photos of medicines; any logo of the Ministry, Pharmacie centrale, CNAM, ANMPS or the Ordre

## Accessibility target

- **Level:** WCAG 2.1 AA (Lighthouse accessibility stays at 100 where it is 100 today)
- **Contrast:** AA for text and UI components on every background, including the petrol rail and powder blue panels
- **Touch / focus:** 48 px minimum targets; visible keyboard focus; never colour alone to carry meaning; `prefers-reduced-motion` honoured everywhere, view transitions included; right-to-left layout correct on public pages in Arabic

## Brand tone and microcopy voice

- **Voice:** Utilitarian & Minimal, in plain French (public pages also in Arabic)
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** Verb-first buttons (« Signaler », « Demander aux pharmacies proches », « Répondre »). One sentence of explanation per screen at most; details behind « Pourquoi ? ». No jargon, no rule codes on screen. Never blame the user. Honest about limits and simulated data, once per screen. All text in `messages/fr/<ns>.json` and `messages/ar/<ns>.json`, never inline. Never write clinical advice (CLAUDE.md rule 11).

## Icon library

- **Library:** Lucide
- **Package / path:** `lucide-react`
- **Notes:** Icons sit next to words. Sizes 16, 20, 24 only; stroke 1.75 (2.25 when active). Medicine forms use the project drawings in `components/medicine/FormPicture.tsx`.

## Agent rules

1. Read this profile, `DESIGN.md` and the project skill `rw-design-system` before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`, `transitions`, `reduced-motion`; type → `typography`; spacing → `spacing`; colour → `colour-palette`; copy → `verbs`, `labels`, `errors`. Before finishing UI, run `rw-screen-review`, which includes `ux-audit`.
3. Use only Lucide and the project's form drawings. No emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog.
